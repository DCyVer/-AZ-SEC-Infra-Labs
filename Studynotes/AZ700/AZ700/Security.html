SECURITY RULE HIERARCHY
When traffic hits a VNet, rules are processed in a "First-Match-Wins" sequence across multiple layers.

  1. Threat Intelligence (The Sieve): If enabled on Azure Firewall, this kills traffic from known malicious IPs/domains before any user rules are even looked at.

  2. Parent Policies (The Mandate): In Firewall Manager, Parent Policies always take precedence over Child Policies, regardless of the priority numbers used in the child.

  3. Rule Type Priority (The Fixed Stack): Within a policy, rule types are processed in this hard-coded order—priority numbers only matter within each bucket:

    • Bucket 1: DNAT Rules (Inbound translation).

    • Bucket 2: Network Rules (L3/L4 filtering by IP/Port).

    • Bucket 3: Application Rules (L7 filtering by FQDN).

    • Kill-Switch: If a Network Rule matches and allows traffic, Application Rules are NEVER evaluated.

  4. Network Security Groups (NSGs): Evaluated at the Subnet then NIC level. Lower numbers (100+) process first

 
5. THE DIAGNOSTIC “SURGERY”
Picking the specific tool for the symptom.

  • Next Hop: "Where is the packet going?" (Troubleshoot UDR/Routes).

  • IP Flow Verify: "Is it the firewall?" (Troubleshoot NSG/ASG).

  • VPN Troubleshoot: "Why is it disconnected?" (Check IKE Phase 1/2).

  • Connection Monitor: "Why is it slow?" (Check Latency/Loss).

🩺 4. Diagnostic "IKEDiagnosticLog" & “NSG Flow Logs”
For the Secure and Monitor domain (15–20% of the exam), you must know the specific log name for the fix. 

  • IKEDiagnosticLog: The only log that shows Phase 1/2 negotiation failures for VPNs.

  • NSG Flow Logs: Required to see which specific rule is dropping a packet in a "Traffic Analytics" dashboard.
