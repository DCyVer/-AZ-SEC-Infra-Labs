Surgical Logic Sync: The "Binary" Check

  • VM⁸ ➔ The Inbound NSG¹⁰ is the final "Yes/No" gate before the packet terminates at the NIC.

  • BACKEND POOL⁸ ➔ The packet hits the VIP/FQDN and terminates only if the Health Probe is green.

  • ON-PREM⁸ ➔ The packet clears the Edge Gateway¹¹ and BGP¹³ to exit the Azure fabric.

  • SERVICE⁸ ➔ The Receiver¹⁷ maps the packet to the PaaS backbone (Private IP or optimized Public path).

  • EXTERNAL ENDPT⁸ ➔ The packet clears the L4 Security¹⁶ stack for an internet or SaaS exit.

2. Azure Internal to Azure External (The "Safe Exit")

  • Company Internal → Internet (Public): Traffic usually flows through an Azure Firewall in a Hub VNet using User-Defined Routes (UDRs). This is where you perform "Egress Filtering."

  • Company Internal → Azure PaaS (e.g., SQL, Storage):

    • Service Endpoints: Traffic stays on the Azure backbone but reaches the Public IP of the service.

    • Private Link / Private Endpoint: The Azure service gets a Private IP inside your VNet. This is the "Gold Standard" for NIS2 compliance in the Netherlands.

 
3. Azure Internal to Azure Internal (The East-West Flow)

  • VNet Peering: Connecting two VNets (e.g., Hub to Spoke). Low latency, high bandwidth.

  • Virtual WAN (vWAN): For large-scale companies (like Philips or Shell), this automates the "Any-to-Any" connectivity between dozens of VNets and branches.

  • The "Exam" Detail: Remember Gateway Transit. If Spoke A wants to use the VPN Gateway in the Hub, the Hub must allow "Gateway Transit" and the Spoke must "Use Remote Gateway."
