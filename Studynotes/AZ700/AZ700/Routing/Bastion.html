Bastion

INSTANT" DECISIONS
"User can't connect to Bastion" ➔ Check NSG Inbound for Internet (443).
"Bastion deployment stuck in 'Failed' state" ➔ Check NSG Inbound for AzureLoadBalancer (443) or UDR for Forced Tunneling.
"Need to RDP into on-prem server via Bastion" ➔ Standard SKU (IP-Connect)

Bastion (2026)
Dev (Free/Min-Cost): 1 subscription/region | Shared MS Cloud | Browser-only |  Private IP | No Native Client | vnet
Basic (Dedicated): ≤ 2/vnets (Peering limit) | Static Public IP | AzureBastionSubnet /26
Standard: ≤ 50/nodes (Scalable) | Native Client (CLI/Putty) | Shareable Links | IP-connect (On-Prem) | Kerberos | Vnet(+hub) Peering  | File transfer 
Premium: Private-only (No PIP) | Session Recording (TLS 1.2+ → Storage) | Zonal Redundancy
 
Subnet: AzureBastionSubnet | Min /26 //N/a for DevSKU
NSG In: GatewayManager +&| Internet  &|  AzureLoadBalancer( health probes)(443) 
NSG Out: AzureCloud (443) + Guest Subnets (22/3389); VirtualNetwork (8080/5701) .
Fail if: UDR: ::/0 to NVA  | OK if UDR for GatewayManager to theInternet
The Basic SKU is the real "trap" here because it sits in the middle with higher costs than Dev but fewer features (like Kerberos) than Standard.
