Azure Private DNS Resolver

[On-Prem DNS](Conditional Forward)  ➔ [Inbound Endpoint IP] ➔ [Azure Private DNS Zone]
[Azure VM] ➔ [Outbound Endpoint([Forwarding Ruleset) ➔ [On-Prem DNS]

Forwarding Ruleset ➔ Must be Linked to the VNet where the Azure VM lives.
Inbound Endpoint ➔ The Private IP you give to the On-Prem DNS admin.
 
INSTANT DECISIONS
"On-prem cannot resolve Private Endpoint FQDN" ➔ Inbound Endpoint .
"Azure VMs need to resolve on-prem .local domains" ➔ Outbound Endpoint + Forwarding Ruleset .
"Centralize DNS for multiple VNets" ➔ Link the Forwarding Ruleset to all VNets.
 

Inbound Endpoint ➔ Receives queries from On-Prem/VNets via Private IP.
Outbound Endpoint ➔ Forwards queries from Azure ➔ On-Prem DNS servers.
Subnet Capacity: Only ONE endpoint (Inbound OR Outbound) per subnet.
VNet Capacity: Only ONE DNS Private Resolver per Virtual Network.
Forwarding Rules ➔ Applied to Outbound Endpoints | Matches domains to target IPs.
Forwarding Ruleset ➔ A separate resource from the Resolver. You can link one Ruleset to multiple VNets, but a VNet can only have one Ruleset linked at a time.

Subnet Lock ➔ Dedicated subnets required (Min /28).
VNet Link ➔ Mandatory to connect a Forwarding Ruleset to a VNet.
Scale ➔ Max 10 Inbound / 10 Outbound endpoints per resolver.
