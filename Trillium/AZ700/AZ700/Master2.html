4. GOVERNANCE & SCALE (THE "HUB" LOGIC)
When a single VNet isn't enough.

  • Virtual Network Manager (AVNM):

    • Trigger: "Manage 100+ VNets dynamically."

    • Tip: Use Security Admin Rules to enforce "Mandatory" rules that local admins can't override.

  • Gateway Transit:

    • Trigger: "Spokes need to reach On-Prem via Hub."

    • Tip: Hub must check "Allow Gateway Transit"; Spoke must check "Use Remote Gateway."

  • VNet Peering Limits:

    • Tip: 500 Peers max. If the question says 1,000, the answer is Virtual WAN.

 
 
🕵️ THE "FINAL PASS" CHECKLIST (THE TRAPS)

  1. Public IP SKUs: You cannot mix Basic Public IPs with Standard Load Balancers. They must both be Standard.

  2. App Gateway vs. Front Door:

    • App Gateway = Regional (VNet Internal).

    • Front Door = Global (Edge).

    • If the app is in Norway East and needs to stay there, pick App Gateway.

  3. WAF Mode: Prevention blocks traffic; Detection only logs it. If the goal is to "Stop the attack," pick Prevention.

  4. Route Server: Used to "exchange" BGP routes between an NVA (like a Cisco Cloud Router) and the Azure VNet. It does not route the data itself; it just shares the "gossip."
