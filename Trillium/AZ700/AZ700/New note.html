In the initial phase of setting up a custom IP address prefix, you are required to ensure that the prefix range is under your ownership in the RIR, such as ARIN or RIPE. Then you will need to create a self-sign certificate to authorize Microsoft to associate the public IP address with the subscription. This must be done before you can go into the deployment phase, which requires this information to configure the prefix in the Azure portal.

You cannot provision the IP prefix without first ensuring ownership or creating the certificate. You need this information to deploy it in the portal. You do not need to request the certificate from the ISP, you can create the certificate yourself. The ASN associated with the IP address must be 8075 for public and 8070 for US Gov Cloud.

 

Azure private DNS Resolver

  1. Provisioning Requirements: Must be deployed in a specific virtual network and region; only one resolver is allowed per VNet.

  2. Subnet Delegation: Every inbound and outbound endpoint requires a dedicated subnet delegated to Microsoft.Network/dnsResolvers .

  3. Inbound Endpoints: Provide a private IP address to receive queries from on-premises or other VNets to resolve Azure Private DNS zones.

  4. Outbound Endpoints: Used to send DNS queries from Azure to on-premises or external DNS servers.

  5. DNS Forwarding Rulesets: Required for outbound resolution to define which domain queries go to which target IP addresses.

  6. VNet Linking: Rulesets must be linked to a VNet for its resources to use the forwarding logic; Private DNS Zones must be linked to the resolver's VNet to be resolvable via the inbound endpoint.

  7. Subnet Sizing: Minimum subnet size of /28 is required for each endpoint.

  8. Hybrid Connectivity: Requires an active VPN or ExpressRoute to facilitate traffic between on-premises and the Azure inbound/outbound endpoints.

  9. NSG Rules: Network Security Groups must allow traffic on port 53 (TCP/UDP) for the endpoint subnets.

  10. Regionality: The resolver and its endpoints must reside in the same region as the VNet they are provisioned in.
